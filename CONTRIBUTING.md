# Contributing to AssayHub Learn

**English** | Türkçe özet aşağıda

Thank you for taking the time to look at AssayHub Learn. The project is maintained by one person, so the process below is kept simple. Issues and pull requests can be written in English or Turkish.

## Before you start: where the content lives

- Module pages are generated by `tools/build.mjs` from the HTML files in `sources/` (Turkish) and the English tables in `i18n/<ID>.en.json`.
- The files in `sources/` are **copies** of prototypes kept in the author's book project, which is not public (see `sources/SOURCES.md`). They are not edited by hand in this repository. The maintainer changes the prototype, copies it here and notes the change in `sources/SOURCES.md`; the SHA-256 of the current copy is stored as `source_sha256` in `i18n/<ID>.en.json`, and the build prints a warning if it no longer matches the file.
- Because of this, a pull request that edits a file in `sources/` cannot be merged as it is. Please report content problems as an issue, or attach your suggested change to an issue or a draft pull request; the maintainer will apply it upstream.
- Module IDs (for example `MD-PBC`) are permanent and printed in the book as QR codes. They are never renamed.
- Results are never invented. A scenario that was not computed is shown as "not computed"; please do not propose filling such gaps with estimated numbers.

## Reporting a software bug

Open an issue on GitHub with:

- the page address (for example `https://learn.assayhub.app/en/md/md-pbc/`) and the module ID;
- the browser and operating system;
- what you did, what you expected and what happened;
- any message from the browser console, if there is one.

## Reporting a scientific or teaching problem

Open an issue and include:

- the module ID, the section and, if possible, the exact sentence or number;
- why you think it is wrong or misleading;
- a reference (paper, manual page, textbook) if you have one.

Numbers on the pages come either from runs listed in the module's `data` field in `modules.json` or from teaching models computed in the browser. Please say which one your report is about if you can tell.

## Turkish and English text

- Turkish is the source language. English pages are generated from `i18n/<ID>.en.json`, which maps Turkish strings to English ones.
- For an English wording or terminology problem, open an issue with the module ID, the current English text and your suggestion. A pull request that edits only an `i18n/<ID>.en.json` table is also welcome.
- After editing a table, run `node tools/i18n.mjs check <ID>` and the full build and checks (below). The build stops if a Turkish source string is no longer found in the table or if Turkish text is left on an English page.
- Shared terminology is listed in `i18n/GLOSSARY.md` and `glossary.json`.
- Please do not use the U+2014 dash in new text; the checks reject it in generated HTML.

## Proposing a new module

Open an issue that describes:

- the learning goal and the intended reader level (basic, intermediate, advanced);
- the book chapter it would belong to, if you know the book;
- the data it would need: whether it is a teaching model that can run in the browser, or real simulation or docking results that would have to be computed in advance, and under which licence those data could be used.

New modules are added to `modules.json` by the maintainer.

## Tests and documentation

Run these before opening a pull request (Node.js 20 or later; nothing to install):

```
node tools/build.mjs
node tools/check.mjs
node --test
```

- `tools/check.mjs` runs the publication checks and the language-rule tests and exits with an error if a rule is broken.
- `node --test` runs the unit tests of the shared browser engine (`tests/mdmini.test.mjs`) and the language tests.
- If you change `assets-src/mdmini.js`, run `node tools/sync-engine.mjs --check`: pages that embed the engine must contain the same copy.
- Documentation fixes (README, CONTRIBUTING, `docs/`) can be sent as pull requests directly.

Please keep pull requests small and focused, and describe what you checked.
